# web: the Machine Room

The UNC 64 as a small browser IDE: the real emulator core (`unc.wasm`), an editor, an assembler, a debugger, a tape deck, and a library of cassettes (`docs/cassettes.md`). It's the developer's tool, and it ships with the game as one file, `machine-room/index.html`, that runs by double-clicking it: no server, no install, no internet. `docs/machine-room.md` is the user's guide (the build puts it beside the page as GUIDE.md).

```sh
scripts/build-machine-room.sh        # build/machine-room/index.html + README.txt: the one file
node scripts/check-machine-room.mjs  # build it, open it from file:// in Playwright, check it (PASS/FAIL)
python3 -m http.server -d web 8064   # development: the same sources, unbundled, at http://localhost:8064
scripts/build-web.sh                 # after changing the core or crates/unc-wasm: rebuilds unc.wasm
```

`check-machine-room.mjs` takes `--browser firefox|webkit` (Playwright's browsers, if installed), `--no-build` and `--shots DIR` (screenshots at 1440 × 900 and 390 wide). It boots the file, runs a sample, saves a cassette and reads it back (the `unCt` chunk and the tape byte for byte), exports it, reads the game's test cassette (`tests/cassettes/`), drops a `.tap` and loads it from the deck, types in and runs BASIC, saves a BASIC project as a type-2 cassette and LOADs and RUNs it, `SAVE`s onto a blank tape with Rec and keeps it as a cassette, runs a bundled BASIC cassette from its tape, runs AURORA from Browse with the video board, and opens `web/` in development mode, with no console errors.

## The one file

`scripts/build-machine-room.mjs` (Node, nothing to install) reads `web/` and writes `build/machine-room/index.html`: `style.css` inline with its fonts as `data:` URLs, every script inline, `unc.wasm` as base64 (`window.UNC_WASM_B64`, which `app.js` uses instead of fetching), and `vendor/codemirror.js` turned from an ES module into a classic script that sets `window.UNCCodeMirror` (its `export{...}` becomes the returned object; its top-level names stay inside a function). `editor.js` stays a module, inline, with its `import {...} from './vendor/codemirror.js'` turned into a destructure of that global: an inline module needs no fetching, so it runs from `file://` in Chrome, Firefox and Safari, and keeps its top-level `await`. The build refuses to write a page that still loads anything from a URL. Beside it go `README.txt` and `LICENSES.txt` (CodeMirror's MIT licences and the fonts' OFL).

## Projects and the machine

A project is `{ title, author, about, machine: { ram, board }, files: { path: text }, main }`. Assembly projects assemble through `assemble_project_input` (the files as `path NUL text NUL ...`, main first; `.include` reads the others), and `make_tape_input` puts the last assembly on a tape. BASIC projects (`main` a `.bas`) run by being typed into the machine as fast as the ROM takes the keys (`#` lines are notes), then `RUN`. Two instances of `unc.wasm` run: the machine, and the bench, which checks your source as you type, builds tapes and takes the pictures for cassette faces, so nothing touches the machine you're debugging but you. The working project is kept in IndexedDB as a draft.

The deck uses `insert_tape_input`, `press_play`, `press_stop`, `rewind_tape`, `eject_tape` (which hands back the tape's bytes, with anything `SAVE` recorded), `set_tape_turbo` (fast load), `tape_counter`, `tape_length` and `tape_status`, and for recording `insert_blank_tape`, `press_record`, `tape_record` and `tape_bytes` (`TAPEX` in `app.js`, feature-detected so an older `unc.wasm` still runs). A BASIC project's cassette is a type-2 tape from `basic_tape`, after the bench has typed the listing in: the same tape `unc-asm --basic prog.bas --tape prog.tap` makes on the command line. A BASIC cassette run from Browse is LOADed, then `RUN` is typed once the tape has stopped. A tape ejected with something new on it is offered to the library. The power switch keeps the tape: its bytes go back into the new machine's deck, rewound.

## The library

Each section of Browse is a source: `{ id, name, note, list() -> entries, get(id) -> cassette }`, plus `writable`, `put` and `remove` for Yours. An entry is `{ id, title, author, about, machine, hasFiles, kind, group, face() -> url }`. Bundled builds its tapes and takes its pictures on the bench the first time they're needed. Yours keeps each cassette's `.unc.png` bytes in IndexedDB (`unc64-machine-room`), or in memory, with a warning, where the browser won't keep them. The online library is a placeholder source (`UNCLibrary.online`) waiting for a `list` and a `get` over the network.

## The editor

Modern tools live outside the machine, and they're optional. The editor is CodeMirror 6:

- **Highlighting** for mnemonics, directives, labels, `@local` labels, constants, numbers (`$`, `%`, decimal, `'c'`), strings, comments, operators, functions, `A`/`X`/`Y`, `*` and `\name` pastes. Names the manual gives to I/O registers, ROM routines and system variables (`BORDER`, `CHROUT`, `CURX`...) have their own colour. BASIC: line numbers, keywords, strings, numbers, `REM`, `#` notes.
- **Errors** from the real assembler, as you type (after a pause of 350 ms): underlined, with the message on hover and a mark in the gutter. They come from the bench, so checking never touches the machine you're debugging. A file main includes is checked as part of the project. An `undefined symbol` that's a name from the manual gets a fix: **Define BORDER = $C020**.
- **Completion** (as you type, or Ctrl+Space): mnemonics and directives where an instruction goes; labels, constants, local labels in scope, functions, and the manual's register, ROM and variable names where a value goes. Picking a manual name the program doesn't define also adds its line, `BORDER  = $C020`, after the constants at the top. BASIC: keywords.
- **Hover** docs: an instruction's operation, flags and every mode with its bytes and cycles, with this line's mode marked; a label's or constant's value and line; a register's, routine's or variable's address and what it does; a directive's or function's syntax; a number in hex, decimal and binary.
- **Cycle counts** in a gutter beside each instruction, `2/3` for a branch (taken: 3). After each assembly they're exact. Select some lines to see their total under the editor. **Cycle counts** turns the gutter off and on; remembered.
- **Keys: Standard / Vim**, remembered. `:w` runs, like the button and Ctrl+Enter.
- **Breakpoints** in the gutter: click beside a line for a red dot (editor.js: a `RangeSet` that moves with edits; app.js resolves each line to its instruction's address after every assembly, moving a dot on a line with no code to the next line with some, and sets it in the machine). When the machine stops, its line is lit (`cm-pc-line`) with an arrow, in whichever file it's in. A dot in the disassembly on a line of the source is the same breakpoint. Kept in the project's draft (`project.breakpoints`), not in cassettes.

Keys in the editor: Ctrl+Enter (Cmd+Enter) runs, in either key mode; Tab types a tab, Shift+Tab unindents; Ctrl+F finds (`/` in Vim); Ctrl+/ comments lines out. F6, F7 and F8 (step over, step, run/pause) work from anywhere on the page. Ctrl+C is STOP only when the screen has the focus.
